AI 하드웨어 메모리 병목 현상 (Memory Wall)

연산 장치(GPU 코어)의 발전 속도를 메모리 대역폭이 따라가지 못하면, 코어는 대기하고 시스템 전체 처리량이 제한된다.

연산력 vs 메모리 대역폭 성장 격차 (2014년 대비)

출처 재구성: NVIDIA K80/P100/V100/A100/H100/B100 공개 스펙 및 공개 기사 자료 기반

연쇄 효과: AI → 빅데이터 → 대형 메모리 요구

AI 모델 고도화
파라미터 증가
빅데이터/긴 컨텍스트
입출력 폭증
대형 메모리 요구
HBM/DRAM 증설
비용/지연/전력 상승
OOM 위험 증가

핵심: AI가 고도화될수록 데이터 이동량이 커지고, 결국 "연산 최적화"보다 "메모리 공급과 이동 최적화"가 성능을 지배한다.

  • 증상: GPU 코어 유휴, TTFT 증가, 처리량 저하
  • 원인: 메모리 대역폭/용량/파편화 한계
  • 대응: Paging, Caching, Quantization, IO-aware 알고리즘
핵심: AI의 다음 병목은 연산이 아니라 메모리 이동과 메모리 비용 02 / 10

Slide 4 · 과거

공간과 시간의 트레이드오프

  • 키워드: Eager Loading, Look-Up Table, TensorFlow 1.x
  • 철학: "연산(시간)은 비싸고, 메모리(공간)는 싸다."
  • 정적 그래프 기반 선점 할당으로 처리량 확보

핵심 포인트

데이터 규모가 통제 가능했던 시절에는 미리 계산하고 메모리에 올려두는 전략이 합리적이었다는 맥락을 설명한다. TensorFlow 1.x의 초기 VRAM 점유도 같은 철학의 산물이다.

핵심: 메모리 선점으로 런타임 연산 최소화 04 / 10
Slide 5 · 전환기

빅데이터 진입과 PyTorch의 승리

  • 키워드: Lazy Evaluation, Dynamic Graph
  • 데이터가 메모리를 초과하는 순간 기존 철학 붕괴

핵심 포인트

Python 제너레이터, Go/Rust 스트림 처리처럼 온디맨드 접근이 실무 표준이 된 흐름을 연결한다. PyTorch의 유연성이 실무 생산성과 디버깅 역량을 끌어올린 지점을 강조한다.

핵심: 필요한 순간에 필요한 데이터만 05 / 10
Slide 6 · LLM 시대 위기

새로운 병목: KV Cache

  • Auto-regressive Generation의 구조적 비용
  • 문맥 길이 증가에 따라 VRAM 사용량 급증
  • 가변 길이 요청이 만드는 파편화(Fragmentation)

핵심 포인트

긴 응답일수록 KV 캐시가 계속 누적되고, 불규칙한 배치 요청에서 메모리 구멍이 커진다는 점을 보여준다. 제한된 프라이빗 환경에서 왜 치명적인지 실제 운영 관점으로 풀어낸다.

핵심: 성능 하락의 주범은 계산량보다 메모리 구조 06 / 10
Slide 7 · 돌파구 1

OS의 지혜: vLLM & PagedAttention

  • 키워드: Paging, Block-based KV 관리
  • 연속 메모리 강제 대신 블록 매핑으로 파편화 완화
  • 테트리스처럼 빈 공간을 활용해 처리량 개선

핵심 포인트

운영체제 가상 메모리 개념을 GPU 인퍼런스에 이식했다는 점을 핵심 메시지로 전달한다. 로컬/온프레미스 LLM 서빙에서 체감 처리량이 크게 오르는 이유를 연결한다.

핵심: 메모리 파편화를 4% 미만 수준으로 억제 07 / 10
Slide 8 · 돌파구 2

FlashAttention + Quantization

  • FlashAttention: HBM IO 최소화, SRAM 중심 계산
  • Quantization: FP16 → INT8/INT4 압축
  • 대역폭 병목 완화 + 모델 메모리 풋프린트 축소

핵심 포인트

하드웨어 특성을 이해한 알고리즘 설계가 성능을 뒤집는다는 메시지를 전달한다. IO를 줄이는 기법과 데이터 크기를 줄이는 기법이 함께 갈 때 실무 최적화가 완성된다.

핵심: IO-aware 알고리즘과 모델 압축의 결합 08 / 10
